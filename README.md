# Pic Expert

Chrome Manifest V3 扩展：在用户已经登录、选择日期并完成查询后，处理**当前查询结果的全部分页**，批量下载完整订单的 SN 码、发票及存在的证明材料图片。

## 规则

- 扩展不负责登录、选择或调整日期、点击查询。用户提交查询后，扩展用网站的列表接口读取同一组筛选条件和全部分页；不会修改条件或切换商户。条件发生变化或接口返回的总数不一致时停止。
- 订单列表、详情、模板和图片均通过网站接口读取；扩展不扫描表格来处理订单，也不打开详情页面。
- 每个新任务的下载目录以交易日期区间开头，再接任务编号；图片、清单和日志共用该目录。旧任务续传沿用原目录。
- 行内出现“材料修改”时整笔跳过。
- SN 码或发票任一缺失时整笔跳过，不下载半套资料。
- 每个参考号建立独立目录，文件名固定为 `SN码` 和 `发票`（保留实际图片格式的扩展名）。
- “证明材料图一”“证明材料图二”“证明材料图三”有图片时也下载，按原标签命名；空项目跳过，不重新编号。接口字段识别不唯一或读取失败时整笔记为失败。
- 下载图片前按实际内容识别 JPEG、PNG、WebP、GIF、BMP；登录页、无法识别的内容或读取失败会整笔跳过或记为失败。
- SN码、发票及本单存在的证明材料均先验证再下载；任一下载失败时尝试清理该订单已生成的全部图片，无法清理的文件路径会记录到运行日志。
- 每次任务只生成一份 `下载清单.csv`，仅保留订单号、参考号、处理结果、原因四列；文件路径记录到运行日志。
- 默认保存到 Chrome 下载目录下的 `pic-expert/<任务时间>/`。

## 安装

1. 使用 Chrome 116 或更高版本，打开 `chrome://extensions/`。
2. 开启“开发者模式”。
3. 选择“加载已解压的扩展程序”，选择本仓库目录。
4. 打开目标订单页面，完成登录、日期选择与查询。
5. 点击扩展图标，选择“开始下载”。

## 页面适配与恢复

- 使用当前标签页的临时授权，探测可访问的 frame，仅在唯一的已查询订单列表页面启动任务；不增加永久网站访问权限。
- 列表使用 `queryList`，详情使用 `queryDtl` 和 `queryTemplateInfo`，图片使用网站的交易材料下载接口。接口请求沿用页面登录令牌；令牌不保存到任务数据或日志。
- 用户查询条件从列表筛选控件读取并映射为网站请求参数。开始时核对接口返回页与页面当前显示页的订单身份和总数；订单处理仍只使用接口数据。断点保存筛选条件、分页大小、总数和当前页订单身份集合；继续前需恢复相同查询。
- 运行期间不要切换页面或修改查询条件；发生变化时扩展会停止。
- 关闭扩展弹窗不影响任务。页面刷新或任务中断后可点击“暂停任务”保存断点，手动返回相同查询后点击“继续上次任务”；“停止任务”结束当前批次并生成清单。清单下载失败可点击“重试下载清单”。
- 弹窗中展开“运行日志”可查看和复制最近 500 条记录，包含时间、步骤、订单身份、下载路径及错误；关闭弹窗后日志仍保留。完整日志按条持久化，可点击“导出完整日志”，每 5,000 条生成一个编号文本文件；开始新任务后弹窗切换显示新任务。
- 任务完成或停止后，弹窗显示成功、跳过、失败统计和清单下载状态；重新打开弹窗仍可查看当前任务摘要。

## 大批量处理与断点

- 月份和查询条件由用户操作；每批只处理已查询结果，扩展不会自动跨月查询。
- 开始下载前先核对列表接口总数与页面结果，再按页读取订单。弹窗显示订单总数、已处理、正在处理及成功、跳过、失败统计；不会预先扫描全部分页，也不需要再次确认。
- 点击“暂停任务”后停止安排新订单，等待当前最多三笔订单结束；需要中断当前等待时再次点击“立即暂停当前等待”。停止和强制暂停会中断在途请求，清理未完成图片，并记录失败和残留路径。
- 继续前手动恢复原查询，扩展核对条件、总条数和断点页订单集合。核对通过后从第一页重新扫描，沿用同一任务编号和目录；完成且下载记录确认文件仍存在的订单不重复下载，之前各页的失败订单和文件缺失订单会重试。已跳过的订单在同一任务内不重复处理。任务已完成但仍有失败订单时，也可点击“继续上次任务”。
- IndexedDB 独立保存订单、下载记录和完整日志；弹窗只读取统计及最近 500 条日志。旧版本任务数据自动迁移，迁移失败时保留原数据。
- 固定同时处理最多三笔订单，同一订单最多同时读取两张图片，总计最多六张图片并发读取。每笔订单全部图片验证通过后逐张保存；不同订单可以同时保存。当前页的在途订单全部结束后才读取下一页。图片网络读取临时错误最多额外重试一次，身份和格式错误不重试。
- 下载优先监听完成事件，并周期补查状态以覆盖事件遗漏和后台重启。
- 结束时只生成四列清单，并记录总数、结果统计和历时。失败任务继续后，结束清单会覆盖同一任务目录下的清单文件。
- 断点只针对上次任务；不同月份的新任务不会自动跨批次去重。站点登录失效、原查询丢失或数据变化时，需要用户处理后重新核对。

## 验证

扩展没有运行时依赖。测试使用 Node.js 自带运行器和开发依赖 fake-indexeddb（仅模拟 IndexedDB，不随扩展运行）。首次验证先安装锁定的测试依赖：

```bash
npm ci
```

再执行：

```bash
npm test
```

同时可以执行：

```bash
npm run check
```

网站接口字段或查询控件可能调整；发生变化时需要同步更新接口适配逻辑。

自动化测试覆盖接口筛选参数映射、请求认证和字段映射、多页扫描、查询变化停止、断点恢复、防重入、配对回滚和清单恢复，也覆盖三笔订单并发、最多六路图片读取、乱序完成、跨页等待、暂停与停止、文件丢失、旧数据迁移、两万条 IndexedDB 存储及完整日志分段导出。IndexedDB 测试使用模拟实现；真实 Chrome 扩展 E2E 和大批量下载速度仍需在本地 Chrome 验证。
